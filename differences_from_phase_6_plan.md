# Differences from the Phase 6 plan

This is the implementation decision log for the active Phase 6 work. It is not a completion report. Audio sample similarity sorting and the XO/Atlas research are excluded from this work. Entries are chronological; see the [current scope audit](#current-scope-audit--2026-10-26) for remaining work rather than treating early checkpoint lists as current status.

## Indexing admission is stricter

Indexing starts with no enrolled roots. Browser visibility and permission to index are separate decisions. Explicit enrollment cannot override the protected-content policy, credential-folder exclusions, or exclusions for repository internals and generated content.

The implementation additionally denies system directory trees and private application configuration (`.config`), alongside the plan's credential locations. Credential/key files are excluded completely from the search inventory rather than merely withholding their embeddings. This avoids persisting secret-related paths and prevents the folder button from creating an index in locations with broad credential exposure. Specific content folders remain eligible, including ordinary folders inside a source-code repository; its `.git` subtree is excluded.

Enrollment and content reads inspect the pinned object's filesystem classification and resolved location, so an ordinary-looking symlink cannot bypass a denial. Root identity and location are retained and revalidated. Core's ordinary-content guard remains authoritative; the search policy adds narrower restrictions without weakening the core guard.

## Standalone model helper and optional Vulkan backend

The model helper adapts only Recall's reviewed MIT C inference shim, through a small standard-library Python JSON-lines process. It does not depend on Recall's crawler, schema, Rust engine, or application lifecycle. Model installation is explicit and checksum-verified at the pinned GGUF revision. Ordinary search startup does not download models or enroll roots.

Prepared media reaches the helper as bounded encoded bytes rather than source pathnames. Guarded readers and external decoders must prepare those bytes in the search coordinator. The helper validates image dimensions and requires bounded 16 kHz mono PCM16 audio. Overlong text/audio is rejected instead of inheriting Recall's silent truncation. The protocol reports finite normalized 768-dimensional float32 output; persistent vector encoding remains a separate index decision.

Vulkan is available as an optional backend in addition to CUDA/CPU. The reused Recall llama artifact has CPU/Vulkan support only. A subsequent workstation check confirmed that the CUDA compiler is installed at `/opt/cuda/bin/nvcc` (CUDA 13.4); the earlier assertion that the compiler was absent was incorrect. After the user's reboot, NVIDIA GPU access works, with loaded and user-space driver versions matching at 615.78.08 and the updated kernel running. The native CUDA/Vulkan/CPU runtime is now built and installed. All three real backend smoke checks passed text/image/audio embeddings, finite normalized 768-dimensional output, a simple relevance comparison and token-budget rejection: `/tmp/clip-search-{cuda,vulkan,cpu}-smoke-20261018.json`. Elapsed checks were 2.126/14.240/4.366 seconds respectively; these are single compatibility runs, not representative warm throughput or retrieval benchmarks. The implementation selects CUDA, then Vulkan, then CPU through fresh owned helpers, checks the backend actually returned, and reports it in index status. Backend changes invalidate the runtime build cache without by themselves invalidating embedding pipeline identity. Installation stages libraries before replacing an idle runtime, with locking and rollback. CPU compute is bounded to four threads.

## Owned reader helpers

Metadata enumeration and source preparation run in the application binary's shared internal worker dispatch. Reader requests/replies and source/media sizes are bounded. A reader pins and revalidates the root and source, rejects symlink traversal and nested-mount descent, and passes owned descriptor-backed inputs to existing external tools. Search enumeration does not perform the ordinary browser's TypeScript payload sniff before admission.

Read-only helpers use an opt-in private process group through core's existing command runner. Timeout/cancellation terminates decoder descendants before draining pipes, including a descendant that outlives its helper. Audio probes/decodes whitelist local protocols and ordinary audio demuxers; disguised playlist inputs cannot fetch network resources or unrelated playlist members. Existing command callers retain their prior lifecycle behavior. The shared CLI dispatch was simplified to keep argument validation centralized as the new worker was added.

## Canonical embedding reuse and root availability (2026-10-18)

This does not prove whole-file equality or replace the planned small-source full-digest optimization.

The transactional v1 migration preserves vectors, backfills only ready rows whose pipeline is known, and leaves pending rows' original pipeline unknown instead of guessing from overwritten file metadata. Reconciliation defers deleting orphan file/vector rows until its admitted work batch drains. Orphan paths are removed promptly; unreferenced file/vector rows are removed at batch completion. Explicit root removal still prunes immediately. ## Tokenizer-aware passages (2026-10-18)
