# EDA file inspection and previews

Open a supported file in Files to inspect its metadata and preview. List strips and file cards use the same guarded decoders. Inspection reads ordinary files up to 32 MiB.

| Files | Preview and inspection | Limits |
| --- | --- | --- |
| Gerber `.gbr`, `.ger` | RS-274X and X2 artwork, units, coordinate format, polarity, aperture counts, file attributes and copper thickness when present. The raster composites dark and clear objects in order. | Content probing separates Gerber `.gbr` from GIMP brushes. The decoder reports unsupported aperture and image transforms. Solid rectangular apertures support legacy linear draws. Other nonstandard sweeps can be approximate. |
| Excellon `.drl`, `.xln` | Drill hits, slots and routed paths in millimeters, with tool diameters, coordinate format and counts from the plotted geometry. | Consecutive cut segments can form one routed path. Tool-up travel is excluded. Commands the flattener cannot interpret are reported. |
| Placement `.pos` | KiCad ASCII and column-qualified CSV or TSV. Inspect reference, package, side, position and rotation. Coordinates convert mm, inches or mils to millimeters. | The parser retains up to 200,000 placements. The viewer scrolls through all retained rows and uses the original placement when selecting a filtered row. |
| HPGL `.hpgl`, plotter `.plt` | Pen strokes, arcs, circles, labels and basic coordinate scaling in plotter units. | Polygon buffers stop a partial preview at `PM`, `EP` or `FP`. Filled rectangles and wedges show a disclosed outline approximation. Device-specific printing, advanced fills and printer containers are outside the preview. |
| KiCad board `.kicad_pcb` and footprint `.kicad_mod` | Board outline dimensions, declared stackup, layers, footprints, net counts, track lengths and basic copper, pad and drill geometry. Board net names can come from legacy declarations or KiCad 10 item records. | Board outline dimensions follow the edge centerlines. Inner copper is grouped. Padstack-specific copper, custom pad shapes and zone fills are simplified. Only a bounded list of net and footprint details is retained. |
| KiCad schematic `.kicad_sch` and symbol library `.kicad_sym` | Sheet title, symbols, wires, buses and labels. Preview uses the embedded symbol definitions and can show units from a local symbol library file. | Only the opened sheet or library is read. External library and hierarchy lookups stay outside the preview. |
| KiCad project `.kicad_pro` | Overview with board rules, net classes, variables and links to same-name local board and schematic files. Source JSON has its own tab. | Companion links require ordinary local files and are verified again when opened. Search and archive preview sources retain their original access scope. |
| Gerber Job `.gbrjob` | Reported board dimensions, copper count, stackup materials, recorded colors and thicknesses, finish and file mapping. | The stackup diagram is schematic. Job paths are displayed as metadata. Optional fields depend on what the exporter wrote. |
| SPICE `.cir`, `.sp`, `.spice` | Searchable top-level connectivity in card order, subcircuits, models, analysis directives and a separate source tab. The thumbnail shows the component distribution. | Unsupported cards can leave a partial parser result. External includes remain metadata. The preview never runs the circuit or its control blocks. |
| SPICE and LTspice `.raw` | ASCII and binary waveforms, including LTspice little-endian mixed-precision, double, complex and single-plot FastAccess. The preview preserves original sample order and peaks within each sweep. | Positive waveform headers distinguish these from camera RAW. The preview retains up to 16 plots, 64 traces per plot and 4,096 samples per trace. Explicit dimensions or axis evidence identify sweep boundaries. Separate step-label logs stay outside the preview. Appended LTspice FastAccess plots are unsupported. |
| LTspice settings `.plt` | Analysis sections, panes, axes and configured trace names on the settings tab. Source remains available. | Waveform samples live in `.raw`. Additional plot expressions, annotations and settings stay in the source excerpt. |
| LTspice schematic `.asc` | Wires, labels, annotations, graphics and rotated or mirrored symbols from ordinary local `.asy` companions. Version and sheet records distinguish schematics from CAN logs and OpenPGP signatures. | Symbol paths resolve under the source directory. Unresolved symbols have labeled placeholders. External libraries, model directives and child-schematic lookups remain outside the preview. The drawing uses approximate text metrics and solid strokes. |

## Deep zoom

KiCad boards, footprints and schematics, along with LTspice schematics, retain the fitted overview and rerasterize the visible region on a cancellable worker. Tiles use the same world transform as the overview and cursor. Board visibility changes invalidate detail from the old layer set. The detail tile is at most 1,600 pixels on a side and compatible tiles stay registered while new detail arrives.

## Compare files

Select the files in Files and choose **Compare selected files**. Gerber and Excellon pairs open in **Artwork**. Select A and B within the same layer when comparing a larger selection of artwork files. Known mismatched Gerber layer roles are rejected. Plain Gerber without a recognized role can still be paired manually. Board sets, archive pairing and guessing the origin of independently exported artwork remain outside the comparison.

- **Changes** uses cyan for additions and orange for removals. **Changes only** hides the reference artwork. **Overlay** has an independent B-opacity slider. Use **A**, **B** or **Hold B** to see one input at the same zoom, pan and cursor coordinates.
- The comparator renders both inputs at the same millimeter origin and resolution after composing their individual dark, clear and image-polarity operations. Exact compares equal raster coverage on that grid. At deep zoom both sources and their diff are rerasterized over the visible region. Changes smaller than a pixel in the overview can appear in detail.
- Edge tolerance offers exact or 10, 25, 50 and 100 µm. It suppresses unmatched coverage when equally covered ink from the other file is within the selected physical radius. The local worker renders a margin outside the tile for this search. Sampling and antialiasing can affect changes near the chosen radius. The displayed pixel counts describe the fit overview. Detail reports its own pitch.
- **Decoded fields** compares placement references and positions, KiCad footprints, board net names, schematic units and labels, footprint pads, symbol library pins, project rules, manufacturing stackup, SPICE element cards and LTspice pane settings. Waveform fields match the analysis, signal and sweep ordinal and report retained axis endpoints and extrema.
- KiCad fields cover the decoded records and counts. Copper topology, pad-level board net rewiring and schematic wire topology need dedicated matching before equivalence can be inferred. Waveform extrema can match while timing or shape differs. HPGL and LTspice schematic comparisons retain byte inspection. These drawings need stable pen-path or symbol and wire matching for a dedicated diff.

The comparison reuses the ordered Gerber and Excellon geometry already displayed in Files. GrbDiff uses Gerbv to produce XOR images and layer comparisons. pcb-diff demonstrates normalized layer pairing and the distinction between single-layer and board-set exports. KiCadiff combines structural diffs with CLI plots and raster classification. KiDiff also rasterizes KiCad CLI exports. Using the in-process geometry keeps both sides on one grid and avoids a second exporter dependency in the preview path. [GrbDiff](https://github.com/dennevi/GrbDiff) [pcb-diff](https://github.com/weiliangng/pcb-diff) [KiCadiff](https://github.com/sksat/kicadiff) [KiDiff](https://github.com/melchiorb/kidiff)

## Parser choices and reference checks

- **Gerber and Excellon.** `lib_gerber_edit` handles both formats and supplies ordered geometry in millimeters, clear polarity, macro evaluation and flattening limits. MakerPnP's `gerber_viewer` provides Gerber rendering with optional egui integration. Retaining the dual-format flattener gives the same geometry and diagnostics to both the desktop viewer and the headless card renderer. The rectangular-draw test compares against a Gerber region with the same analytical boundary. [lib_gerber_edit](https://docs.rs/lib_gerber_edit/latest/lib_gerber_edit/) [gerber_viewer](https://github.com/MakerPnP/gerber-viewer)
- **HPGL.** `nom-hpgl` parses a command subset and leaves drawing semantics to the caller. The alpha `ezhpgl-core` interpreter has wider coverage, including polygons and clipping. Adopting it would replace the current pen travel, source-line interaction and cancellation integration. The current preview exposes its polygon and fill limits. [nom-hpgl](https://docs.rs/nom-hpgl/latest/nom_hpgl/) [ezhpgl](https://github.com/monozukuri-ai/ezhpgl) [HP reference manual](https://www.hp.com/ctg/Manual/bpl13211.pdf)
- **KiCad.** The existing `eda-view` S-expression parser and schematic scene renderer cover the read path. `kiutils_kicad` offers a typed, lossless document model and version diagnostics for editing. The preview already has the syntax tree and only needs a bounded projection of board geometry. KiCad 10.0.8 was used to upgrade a reference board and export a routed drill, copper Gerber and Gerber Job. The regression compares the slot endpoints and copper flash center to those exports. [eda-view](https://docs.rs/eda-view/latest/eda_view/) [kiutils-kicad](https://github.com/Milind220/kiutils-rs) [KiCad format notes](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/)
- **SPICE.** `dune-netlist` supplies circuit elements and `dune-raw` handles SPICE3 and ngspice row-oriented data. The published `spice_rawfile` 0.0.1 crate has no decoder. Spicelib documents and reads the LTspice FastAccess column layout. The Rust preview reads those columns directly from the bounded payload and reuses the established sweep and peak reduction. Tests cover mixed precision, double, complex, stepped and truncated data, plus the binary operating-point output of an ngspice 47 resistor-divider run. [dune-raw](https://docs.rs/dune-raw/latest/dune_raw/) [spice_rawfile 0.0.1 source](https://docs.rs/crate/spice_rawfile/0.0.1/source/src/lib.rs) [PyLTSpice RAW File Structure](https://pyltspice.readthedocs.io/en/latest/varia/raw_file.html)

- **LTspice drawings.** The Analog Devices format guide documents Windows-1252 and the drawing records. The KiCad importer reference supplies orientation and arc conventions. The preview reuses the existing vector scene and stroke font. [Analog Devices schematic guide](https://github.com/analogdevicesinc/ltspice-reference/blob/main/ai_ref/SCHEMATIC-REFERENCE.md) [KiCad LTspice format notes](https://dev-docs.kicad.org/en/import-formats/ltspice/)

## Follow-up verification

- KiCad 10.0.8 exported matching copper, board-outline and routed drill pairs. Identical exports and the unchanged outline produced zero raster differences. Moving the connector 2 mm produced additions and removals on copper and in the drill file.
- The deep-zoom regression reveals a 4 µm clear flash that produces no visible differences in the fit raster. A separate case verifies that equal artwork stays unchanged and that two raster densities give the same tolerance decision with matching ink across a tile boundary.
- In an unoptimized local run, a 60,000-segment board took 242 ms to rasterize at fit and 552 ms at the largest overview size. The 1,100 × 800 detail tile took 13 ms and used 3.52 MB. The same detail size took 8 ms for the KiCad ECC83 demo board and 2 ms for its schematic. [KiCad ECC83 files](https://github.com/KiCad/kicad-source-mirror/tree/10.0.8/demos/ecc83)
- A dense Gerber pair with 60,000 flashes in each 1.4 MB file took 408–499 ms for the overview and 140–151 ms for the 1,100 × 800 detail at 128 px/mm. These timings measure raster work on the worker. UI tests check that switching A and B preserves the physical cursor and that the overview is still available at deep zoom.
- Both solver runs reopened through the common RAW decoder. [SPICE solver evaluation](spice_solver_evaluation.md)
