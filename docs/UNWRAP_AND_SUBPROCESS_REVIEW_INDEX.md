# Reviewed unwrap and command sites

Snapshot after the fixes in this review. Line numbers describe this revision; adjacent calls on one line are counted separately. Test-only code is excluded using syntax/attributes and parent module checks, with compiled production sites independently checked through Clippy. This includes conditional source and maintained vendor forks, not registry sources.

## Unwrap decisions

286 calls outside tests/examples, including 11 calls in the offline fixture generator and four in the standalone GPL helper. No blanket replacement with defaults or `expect` was performed.

**B — bounded binary conversion:** a prior length check, exact read or checked cursor establishes the requested array width. Invalid input still returns the existing parse error.

**P — shared-state poison:** search snapshots/dispatch, paired ranking indexes, playback racks, video delivery epochs and privacy display state have coupled invariants. Blindly recovering a poisoned guard could publish inconsistent state or lose accepted work. These retain a possible panic after an earlier programming/engine panic. Search shutdown cleanup already tolerates poison; small optional clipboard ownership was safely repaired separately.

**J — worker joins:** image-comparison workers use checked image ranges. Normal image errors propagate as Results; a decoder or internal worker panic still propagates through join. App job/render boundaries contain it, but direct library callers may observe a panic.

**T — vendor pool startup:** thread creation can fail under OS resource exhaustion. The application catches the vendor rendering panic; a trivial fallback would still encounter internal Rayon pool operations and is not a safe partial fix.
