# /dev and /sys implementation status

Authoritative requirements: `dev_and_sys_file_manager_spec.md`. The goal remains the full four-phase implementation and its acceptance cases. This file tracks the implementation history; its earlier Outstanding/remaining lists describe those development points. See [System Preview Conformance](System%20Preview%20Conformance.md) for the current reconciled requirement and acceptance matrix. The approved initial implementation and acceptance reconciliation are complete; the original scope is unchanged.

## Implemented foundation

- Shared kernel-interface routing uses file type and pinned-handle filesystem identity, including aliases. Ordinary content readers reject devices, sysfs, procfs, cgroupfs, tracefs, debugfs, and efivarfs before reading. Device infrastructure directories and devpts use system inspection; ordinary `/dev/shm` files keep ordinary handling.
- Ordinary files are reopened through their pinned descriptors to prevent pathname substitution into a device. External probes using `CommandRequest` can inherit a pinned ordinary-content input descriptor.
- Clipboard item hydration, Shelf regular-file preview dispatch, audio decoding, and workbench file sources use the shared ordinary-content policy. The remaining entry-point audit is listed below.
- Batch mutation preflight checks all source trees before effects; copy readers revalidate. Protected destinations and naming operations are rejected. Missing ordinary sources remain per-item failures so completed items in ordinary batches keep their results.
- Generic system strips and the read-only inspector use a separate two-worker queue and tracked helper processes. System rows/inspectors enforce a two-second response deadline even when preliminary metadata work stalls. Deadline/cancellation does not synchronously wait for a blocked helper to exit. Parent-death signaling is installed; live retired children continue to occupy admission slots until actually reaped.
- Typed facts retain raw and formatted values, units, source, collection time, and distinct observation outcomes. A subsystem-scoped registry permits documented attributes; unknown attributes remain metadata-only. Attribute payload reads are capped at 64 KiB and share a 1 MiB / 64-read object budget.
- Initial rules cover USB/PCI identity, network state, block/loop/queue/device-mapper attributes, NVMe controllers/subsystems, CPU/cache/frequency, hwmon/thermal, batteries, and several embedded/platform classes. Specialized family collectors and visualizations are tracked below; attribute-registry coverage alone does not establish family completion.
- Namespace identity and object fingerprints determine shared cache/lifetime keys. `/dev` access interfaces and their canonical `/sys` object share observations while interface permissions, source identity, and pseudo-device semantics remain separate. Attribute views have independent keys. Unknown namespace identity prevents snapshot reuse.
- Udev invalidation is supplemented by bounded visible refresh. Rows refresh no more often than five seconds; the inspector no more often than one second. Failed refreshes retain old observations with age/error disclosure and back off. Hidden preview work is retired.
- Atomic helper checkpoints preserve facts collected before a later read stalls. Parent acceptance revalidates interface/kernel identity and namespace. Failed refreshes retain prior field values with their original ages and failure outcomes; replacement generations cannot inherit them.
- Pseudo-device semantics are derived from major/minor identity without consuming device content.
- Directory double-click navigates; the embedded inspection icon and context action open the inspector. Ctrl/Shift and multi-selection mode keep row selection behavior.
- Inspector-local Back, Refresh, copying collected values, and identity-checked relationship inspection/browse/reveal are available. Browser navigation uses ordinary history and folder-change hooks. Revealing a target selects it after asynchronous directory loading and exposes hidden targets when necessary.

## Phase 2 storage implementation

- Disk/partition strips show proportional observed extents, selected-partition highlighting, capacity, and mount information. Hover reports partition filesystem type, label and UUID from udev metadata when available, plus mount associations. The same diagram appears in the shared inspector.
- Gaps are outside observed partition ranges, not inferred free space. Partial scans and retained diagrams disclose their status. Extents use checked 512-byte sector conversion; overflow and out-of-capacity ranges are rejected.
- Ordinary mountinfo major/minor matching handles conventional filesystems; Btrfs mount sources are resolved using metadata-only pinned classification, preserving subvolume roots and namespace context. Bind mounts and non-UTF-8 path bytes survive parsing and helper serialization.
- Loop attributes include backing path, offset, size limit, direct I/O, partition scanning, read-only and autoclear. Unattached status requires an observed zero size and missing backing-file attribute. Backing files link to ordinary browser navigation.
- Device-mapper names/UUIDs, bounded holders/slaves, and dependency chains are shown. LUKS/LVM UUID markers are explicitly identified as markers; target tables are not queried or guessed. Ordinary mount/backing-file links browse/reveal, while kernel links inspect.
- NVMe controller/subsystem rules expose model, serial, firmware, transport, state, controller IDs and queue metadata. Namespace/controller and exposed-sensor relationships are navigable. Secrets, reset/rescan/delete controls and `nuse` (which triggers Identify Namespace) stay outside the passive allowlist.
- Block `diskseq` participates in lifetime generations, including loop reuse. Inspector scroll positions are keyed by object path and lifetime, avoiding inherited scroll from unrelated devices.
- Bounds: the existing 64-attribute / 1 MiB object budget remains shared. Partition scans inspect at most 512 entries and retain at most 12 extents; dependency groups retain at most 32 links. Mountinfo input is capped at 4 MiB / 8192 records, with at most 128 source resolutions and associated mount entries. NVMe child scans inspect at most 128 entries. These are disclosed observations, not exhaustive inventories when bounds or access prevent completion.

Remaining storage work: reverse association from ordinary image files to live loops; broader synthetic/device-mapper/loop fixture coverage; association-source coverage refinements; complete sharing of underlying bus identity across distinct kernel access objects; richer MD RAID/Btrfs/filesystem state and topology in Phase 3. No claim of full Phase 2 completion is made.

## Phase 2 USB/serial implementation

- Shared USB strips show product, USB-facing VID:PID and negotiated speed. A compact topology shows PCI host controller, USB hub/port ancestry, interfaces and endpoints, with explicit parent relationships and coverage in the inspector.
- Interface metadata includes alternate setting, class/subclass/protocol, driver and endpoint count. Endpoint metadata includes direction, transfer type, maximum packet payload and polling interval. Endpoint directories remain kernel relationships; no endpoint `/dev` nodes are invented.
- `ttyUSB*`/`ttyACM*` previews find USB parents and driver bindings using metadata only. They explicitly avoid discovering a baud rate or asserting the identity of a downstream microcontroller.
- Associated access nodes are discovered through a metadata-only descendant scan, capped at depth three and 128 directories per interface. Device/interface inventory scans cap at 128 entries and eight interfaces; endpoint topology caps at 40 nodes and each interface scan at 64 entries. The existing attribute/read/output/helper limits still apply.
- Passive helpers execute the running executable inode through `/proc/self/exe`, preserving protocol compatibility and collection after a rebuild unlinks the old binary.
- Remaining USB work includes broader permission/removal/budget fixtures, tighter per-object failure coverage, full shared physical-identity caching across different access interfaces, more complete associated-node inventory for deeper driver layouts, and the separately budgeted explicit serial-configuration inspection described by the spec.

## Phase 2 PCI/display implementation

- PCI strips show the device address, driver, observed negotiated link speed/width and IOMMU group. Shared topology connects PCI bridges to bound child interfaces. BAR/resource ranges come from the read-only ASCII `resource` attribute; config space, mapped BAR payloads and ROM contents remain excluded.
- IOMMU peer links describe group membership, explicitly without asserting VFIO assignment. Resource range arithmetic is checked; zero unallocated entries are omitted. Child inventories reuse the bounded metadata walker.
- DRM strips distinguish primary, render, legacy control and connector interfaces and link their underlying GPU and sibling interfaces. Connector strips summarize the selected output; primary/render strips summarize the observed connected outputs.
- Connector facts include connection status, encoder association and advertised mode names. Connected/enabled/advertised facts do not establish a queried active mode. Collection never opens a DRM node, becomes DRM master, or reads a framebuffer.
- Binary EDID reads are restricted to a DRM connector's `edid` attribute and share the existing read/byte budgets. Header, exact block count and every block checksum are validated. Base identity, manufacture/model year, physical dimensions and base detailed timings are shown. Interlaced timings remain explicitly raw advertised DTDs.
- Remaining display work: full extension timing interpretation, deterministic permission/removal/budget fixtures, richer displays where information is available without active probing, and shared physical GPU identity across distinct access objects. The current topology view has the existing compact cell limit; incomplete connector inventories retain coverage status.

## Phase 2 shared process and terminal associations

- One asynchronous process snapshot cache is shared across eligible visible device/access rows and inspectors. Requests are coalesced, throttled to five seconds, scoped to the current namespace view, and discarded after ten seconds. It has one bounded background job lane and uses the existing tracked helper facility; it does not add untracked child processes.
- Collection reads documented `/proc/PID/stat` identity/session fields and pins descriptor targets with `O_PATH` for metadata only. No terminal data, process memory, command line or scrollback is read. Process stat is checked before and after FD inspection; changed PID/start-time pairs lose the collected descriptors.
- Bounds: 4096 proc entries, 1024 PIDs, 32768 total FDs, 256 FDs per PID, 500 ms scan wall time, 4 KiB per stat, 768 KiB retained serialized process records and the existing 1 MiB helper response cap. At most 32 matching process links are presented per object. Permission gaps, disappearance, malformed metadata, other errors and partial/time-limited scans remain explicit.
- Descriptor matches compare filesystem device, inode and device number; this conservatively avoids merging separate devpts instances or recycled PTYs. Observations mean an accessible process had a descriptor open at collection time, not active use or exclusive ownership. Additional device-node aliases created as distinct inodes still require broader underlying-object association work.
- Terminal relationships require both matching descriptor identity and matching controlling-terminal number. Session and process-group fields identify observed foreground-group members and session leaders; leaders are explicitly not assumed to be shells. Data retains the process scan's observation time.
- Process links inspect bounded identity/session information. They carry the observed PID start tick, which is checked against the isolated helper result before acceptance; a reused PID cannot open as the prior process. Process links do not browse arbitrary proc contents. The fact table wraps long values within the inspector viewport.
- Remaining terminal work: controlling-terminal associations without an accessible matching FD, virtual-console active/allocation semantics, console/TTY aliases, richer job/session presentation, emulator confidence, directory summaries, and broader namespace/permission/stall/navigation fixtures. The common process snapshot still needs incremental/checkpoint response transport for a stalled scan and more comprehensive cancellation/coalescing fixtures.

## Phase 2 CPU/cache/frequency implementation

- Logical CPU previews show kernel-reported package/core identifiers, online membership, SMT siblings and reported/requested policy frequency. Topology, NUMA-node, cache and frequency-policy relationships remain navigable. Modern core/package CPU lists and legacy sibling lists stay distinct observed fields; architecture defaults are disclosed rather than treated as proof of a hardware arrangement.
- CPU root, logical CPU, cache, policy and typed CPU-list attribute previews share a membership renderer. It represents the union of all observed CPU sets, including sparse IDs and offline IDs outside the possible set, in at most 128 deterministic aggregate cells. Each cell retains per-set counts and unknown status; no million-element ID/widget allocation is needed. Selected logical CPUs are outlined and a focused source set is highlighted. Cell text and outlines reuse the shared palette contrast helper, including translucent retained observations.
- Membership sets cover online, present, possible, offline, isolated and full-tickless CPUs, plus relevant SMT, cache-sharing, policy and directly inspected attribute sets. Empty sets remain observed empty; denied/malformed/missing sets remain unavailable. Attribute previews retain their own title and source-set summary.
- Cache previews include level, type, size, associativity, sets, line size and shared CPUs when exposed. Kernel `K` sizes are converted from KiB to checked byte values and reuse the file-manager size formatter. Individual CPU inspectors include bounded cache summaries and links to cache objects.
- Policy previews expose governor, scaling driver, policy/hardware limits and related/affected CPUs. Policy CPU lists use the documented whitespace-separated form. Reported/requested policy frequency is explicitly distinguished from hardware frequency and never claimed to be a guaranteed instantaneous clock.
- Linux character majors 202/203 link MSR/CPUID interfaces to the corresponding sysfs logical CPU without opening those devices. Shared observations preserve the low-level access title and the sysfs CPU object's separate semantic role.
- The existing 64-read / 1 MiB object budget and helper deadlines remain in force. Relationship scans cap at 256 entries and 96 displayed links. Cache inventory uses the shared 128-entry/eight-result child scan. Partial or failed inventories preserve their observation status; cached CPU diagrams retain age/error disclosure without crossing lifetimes.
- Remaining CPU work: more architecture-specific/denied/hotplug/large-inventory fixtures and broader alias/lifetime acceptance. NUMA memory and distance visualizations remain in Phase 4; this implementation adds CPU-to-node links only. The common static-versus-dynamic caching audit is still outstanding.

## Phase 2 sensor/thermal/power-supply implementation

- Hardware-monitoring strips use driver identity and channel labels without assuming a channel is a CPU/GPU sensor. Typed temperature, voltage, current, power, energy, fan and PWM observations retain units, source, age, flags and failure outcomes. PWM duty uses the documented 0–255 scale; opaque/unverified thermistor readings remain raw and do not get normalized plots.
- Compact bars use compatible observed values/limits. They do not fabricate safe temperatures or warning bands. Fresh kernel alarm/fault flags can highlight a reading; retained flags do not assert a current alarm. The row shows up to four series, while the inspector shows collected measurements, threshold values and their source data.
- Thermal-zone trip temperature/type/hysteresis and cooling-device trip bindings have strict dynamic registry entries; emulation and unknown controls remain excluded. Cooling-device state is ordinal, shown with its exposed maximum without converting it to a physical percentage. Metadata-only cooling/hardware/hwmon links are bounded and navigable when exposed.
- Supply previews show type/status, reported capacity, energy and charge independently, and available voltage/current/power/temperature. Full/design estimates require compatible units, positive design capacity and a meaningful battery context. Values above 100% remain visible, and the derived estimate stays separate from the kernel health state. Its full/design inputs remain inspectable.
- Known telemetry attribute files keep their native field value/unit as the preview focus. This prevents an energy-full attribute from being presented as a derived percent ratio. No extra collection is admitted for unknown attributes.
- Diagrams are rebuilt from retained typed fields after failed refreshes, preserving field ages/outcomes and refusing to cross namespace/lifetime changes. Documented attributes match by source identity/origin rather than their mutable display label, so a failed sensor-label read cannot hide the retained input value.
- NVMe 0 K / 65535 K default threshold encodings are preserved in facts and annotations but excluded from meaningful plot bounds. This behavior follows the NVMe defaults and the kernel's conversion; arbitrary numeric bounds are not invented for sensors without limits.
- Collection reuses the existing read/byte/helper budgets. Dynamic field scans cap at 512 entries and 48 selected attributes, with disclosed truncation; thermal relationship scans cap at 128 entries. Shared scoped observation lookup reuses both the typed value and its original observation time.
- Remaining work: expanded driver-specific/permission/removal/stall fixtures, thermal-zone-to-hwmon association coverage beyond exposed direct links, large-channel prioritization and partial-inventory acceptance, explicit captured supply-present/online/health metadata in compact graphics, and live battery/supply acceptance on hardware where those interfaces are available. This host has hwmon/cooling objects but no power-supply entries; supply behavior currently has synthetic typed-data coverage.

## Phase 2 network implementation

- Interface strips show the mounted-view name, Ethernet/loopback/wireless or reported link kind, exposed driver, carrier, MTU and meaningful negotiated speed/duplex. Virtual interfaces do not receive fabricated physical speeds. Queue-directory counts and reported TX/RX queue counts stay separate observations.
- A bounded rtnetlink backend enriches the inspector with current-namespace link classification, configured administrative state, VLAN IDs, master/lower-interface references and assigned IPv4/IPv6 records. Point-to-point local and peer addresses are distinguished; scope and flags disclose tentative/DAD-failed addresses without claiming usability or reachability.
- The backend has no configuration operation: its request builder admits only `RTM_GETLINK` and `RTM_GETADDR`, kernel PID zero and zero multicast groups. It neither subscribes, switches namespaces nor creates packet/network traffic. Kernel sender, sequence, lengths, alignment, scalar sizes and address prefixes are checked; kernel errors, overruns and interrupted dumps cannot become successful empty inventories.
- Mounted name/index/address correlation and known namespace identity are required before importing current-namespace observations. Missing MAC identity does not count as a verified match. Foreign/unknown peer namespace references never become local path relationships. Local related-link paths recheck exposed index/address through the shared bounded attribute reader.
- Exposed lower/upper relationships reuse the shared topology/inspector. At most three address strings appear in the compact strip; at most 64 address facts are displayed with the returned record count and explicit truncation. No historical bandwidth graphs or traffic counters are collected.
- Bounds: one query socket per helper observation, shared 500 ms wall limit, 2 MiB responses, 128 datagrams, 64 KiB per datagram, 1024 response records and 256 attributes per frame. Queue/relationship inventories cap at 128 entries and relationship diagrams at 32 nodes. Existing helper/read/output budgets remain in force.
- Remaining network work: broader live bridge/bond/VLAN/veth/TUN/TAP/WireGuard fixtures, interrupted/permission/removal/large-inventory UI acceptance, richer master/member diagram ordering, explicit topology subtype details, static observation coalescing across visible interfaces, and mounted-view versus current-network-namespace alias/mismatch coverage. Routes and neighbor-table inspection are not yet added; current results are explicitly not a complete network-configuration inventory.

- Input device, event, mouse, joystick, HID and hidraw objects now have shared passive identity and interface topology. Event/mouse/joystick access nodes use their input-device parent; HID access nodes use their registered HID parent. USB grouping reuses the common physical USB parent resolver. Bluetooth, virtual, I²C and other bus IDs remain kernel-reported metadata, without inventing remote hardware identity or merging devices through a shared host controller.
- Input metadata includes name, physical/unique identifiers, vendor/product/bus/version IDs, event/key/relative/absolute/switch/LED/force-feedback capability bitmaps, and properties. Event categories decode the bounded 32-bit `EV_MAX` mask; `EV_KEY` describes keys/buttons and does not assert keyboard identity or live key state.

- HID report descriptors are read only from the HID subsystem's documented sysfs `report_descriptor`. Binary metadata validation now shares the EDID reader's existing pinned-filesystem/read-budget mechanism. Direct descriptor inspection uses the specialized binary-attribute dispatcher; generic unknown attributes remain metadata-only.

## Phase 3 MTD/UBI implementation

- MTD flash/partition, read-only MTD access, mtdblock, UBI device/volume, ubiblock and UBI management objects now route to specialized passive metadata. Access aliases resolve their corresponding geometry objects without opening flash or volume payloads. Read-only access interfaces remain distinct from the underlying kernel write-capability flags.
- The attribute registry exposes byte geometry, OOB/ECC data, aggregate corrected-bit/ECC-failure/bad/BBT counts, erase-region counts, kernel flags, UBI good-PEB/available-LEB counts, volume reservations, maximum erase counters, bad-block pools, read-only mode, corruption and update markers. Byte and counter fields use checked unsigned parsing; negative values are not accepted as geometry.
- Known MTD parent/partition relationships reuse the existing storage extent model and proportional renderer. Offsets are parent-relative bytes; overflow, missing capacity, zero ranges and out-of-capacity extents fail explicitly. Flash tooltips describe geometry without filesystem/UUID or per-block-health claims. Aggregate bad-block counts never generate guessed damaged-block locations.
- UBI backing links resolve canonical MTD objects and require a matching registered object. Volume reservations use checked reserved-eraseblock × logical-eraseblock multiplication and appear as a logical topology, with no invented fixed physical offset or filesystem-use percentage. Canonical class targets avoid duplicate alias paths and fictitious backing links when indices are unavailable/out of range.
- Bounds reuse the semantic reader, byte/read budgets, helper isolation and shared child selector. Partition inventory retains at most 12 entries; UBI controller/volume scans retain at most 16. Inventory failures/truncation are reported, and unknown metadata remains unavailable rather than guessed.
- Verification: 211 file-manager tests pass with one ignored. Connector interpretation follows the [DRM sysfs implementation](https://raw.githubusercontent.com/torvalds/linux/master/drivers/gpu/drm/drm_sysfs.c): `enabled` tests encoder association, `modes` exposes advertised names, and `edid` returns the cached connector property.

Process identity/session fields follow [proc_pid_stat(5)](https://www.man7.org/linux/man-pages/man5/proc_pid_stat.5.html); descriptor metadata and permission restrictions follow [proc_pid_fd(5)](https://www.man7.org/linux/man-pages/man5/proc_pid_fd.5.html).

Frequency interpretation follows the [CPU performance scaling documentation](https://www.kernel.org/doc/html/latest/admin-guide/pm/cpufreq.html). Low-level CPU device mappings follow the [Linux device-number registry](https://raw.githubusercontent.com/torvalds/linux/master/Documentation/admin-guide/devices.txt).

Sensor units and channel semantics follow the [hwmon sysfs ABI](https://docs.kernel.org/hwmon/sysfs-interface.html); thermal trips and ordinal cooling states follow the [thermal sysfs guide](https://docs.kernel.org/driver-api/thermal/sysfs-api.html). Battery quantities follow the [power-supply class documentation](https://docs.kernel.org/power/power_supply_class.html). NVMe endpoint interpretation follows [Base Specification 2.0a, section 5.21.1.3](https://nvmexpress.org/wp-content/uploads/NVMe-NVM-Express-2.0a-2021.07.26-Ratified.pdf) and the [kernel NVMe hwmon implementation](https://raw.githubusercontent.com/torvalds/linux/master/drivers/nvme/host/hwmon.c).

Network framing and operations follow [rtnetlink(7)](https://www.man7.org/linux/man-pages/man7/rtnetlink.7.html), [netlink(7)](https://www.man7.org/linux/man-pages/man7/netlink.7.html) and the [kernel rt-link specification](https://kernel.org/doc/html/latest/netlink/specs/rt-link.html).
