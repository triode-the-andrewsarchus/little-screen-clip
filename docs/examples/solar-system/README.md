# Solar System trajectory imports

Open a supported file in Files to see its path around the Sun. Scrub the UTC timeline to move the marker between recorded positions. Scroll over the timeline to zoom down to millisecond precision. **Fit trajectory** brings the path back into view. Imports are limited to 16 MiB and require at least two strictly increasing epochs.

| Source | How to prepare the file | Example |
| --- | --- | --- |
| JPL Horizons | Export a geometric **Vector Table** with Sun body center (`500@10`), J2000 ecliptic or ICRF axes, AU or kilometers, and XYZ positions. Save the complete report as text, with either kind of row formatting, or save the Horizons API JSON response. | [Horizons text reports](../horizons/README.md), [Mars API JSON](../horizons/Mars-ICRF.json) |
| CCSDS Orbit Ephemeris Message (OEM) | Use one segment with `CENTER_NAME = SUN`, `REF_FRAME = ICRF`, and UTC, TAI, TT, GPS, or TDB epochs. The viewer uses the kilometer positions and displays samples within the declared usable interval. Both CCSDS key-value notation (KVN) and XML work. | [Mars KVN](Mars-ICRF.oem), [Mars XML](Mars-ICRF.xml) |
| CSV from a simulation or notebook | Start with `# Sun-centered J2000 ecliptic` on its own line. Follow it with `utc,x_au,y_au,z_au` or `utc,x_km,y_km,z_km`, then one timestamp and XYZ triple per row. Use an RFC 3339 timestamp such as `2024-01-01T00:00:00Z`. | [Synthetic example](Example-orbit.csv) |

The Mars files contain the same three samples from Horizons at daily intervals starting 2024-01-01 TDB. The API query used `COMMAND=499`, `EPHEM_TYPE=VECTORS`, `CENTER=500@10`, `REF_PLANE=FRAME`, `REF_SYSTEM=ICRF`, `OUT_UNITS=KM-S`, and `VEC_TABLE=2`. The viewer rotates ICRF positions into the J2000 ecliptic. [Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html), [Horizons reference frames](https://ssd.jpl.nasa.gov/horizons/manual.html#frames), [CCSDS Orbit Data Messages](https://ccsds.org/Pubs/502x0b3e1.pdf)

The view displays one imported trajectory at a time and interpolates linearly between positions. It uses approximate catalog positions for background planets and moons. For a flyby or other rapid change in direction, request closely spaced source samples. Use source ephemeris tooling when the analysis depends on encounter distances, velocities, covariance, or the OEM's specified interpolation method.

## Workflow coverage

| Workflow | What the view supports and where it falls short |
| --- | --- |
| Education, hobby physics, and inspecting a precomputed orbit | Open a small-body path from Horizons or plot time-stamped XYZ output from a simulation. The fit control and timeline are enough for visual inspection of an individual path. Comparing runs, investigating residuals, and exporting a reproducible set of states require additional tooling. [JPL Orbits & Ephemerides](https://ssd.jpl.nasa.gov/orbits.html) |
| Scientific tables | ECSV and VOTable carry units and column metadata for many kinds of measurements. Plotting a trajectory from those containers requires choosing the epoch and position columns and establishing their origin, frame, and time scale. A notebook can export that selection using the CSV convention above. [Astropy ECSV](https://docs.astropy.org/en/stable/io/ascii/ecsv.html), [IVOA VOTable](https://ivoa.net/documents/VOTable/20250116/REC-VOTable-1.5.html) |
| Backyard observing and satellite passes | Finding an object in the sky requires an observing location, horizon, and apparent RA/Dec or altitude/azimuth. Horizons observer tables carry those quantities. Importing the MPC asteroid or comet catalogs would also need element propagation and target selection. TLE and CelesTrak OMM require Earth-centered SGP4 propagation and a topocentric sky view. [Horizons observer tables](https://ssd.jpl.nasa.gov/horizons/manual.html#obsquan), [MPC orbit plotting](https://docs.minorplanetcenter.net/tutorials/notebooks/mpc_tutorial_orbit_plotting/), [Stellarium user guide](https://stellarium.org/files/guide.pdf), [CelesTrak GP data formats](https://celestrak.org/NORAD/documentation/gp-data-formats.php) |
| Astrophotography, astrometry, and photometry | FITS images and tables, SER capture sequences, ADES astrometry, and AAVSO photometry need image and sky-coordinate handling, observation overlays, or light curves. Those files do not supply heliocentric XYZ tracks. [NASA FITS](https://science.data.nasa.gov/fits), [Siril sequence formats](https://siril.readthedocs.io/en/latest/Sequences.html), [MPC ADES](https://docs.minorplanetcenter.net/mpc-ops-docs/observations/ades-format/), [AAVSO Extended Format](https://archive.aavso.org/aavso-extended-file-format/) |
| Mission and planetary ephemeris work | Sun-centered OEM and Horizons are usable for a visual check. General OEM support needs mixed origins and frames, multiple segments with explicit gaps, and the declared interpolation and time systems. The Earth sky uses a specific installed DE440 kernel. Opening arbitrary SPICE SPK files requires target selection, evaluation by segment type, chained centers and frames, and kernel coverage handling. OPM and OMM supply orbit parameters or mean elements that have to be propagated. [CCSDS Orbit Data Messages](https://ccsds.org/Pubs/502x0b3e1.pdf), [NAIF SPK Required Reading](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/req/spk.html) |
