## Conflicts and unverified ownership

- The Quick Palette search field intentionally interprets selected single-character inputs as commands. Its query-prefix route and focused-edit route are intentionally staged across frames. Arrow/Enter palette handling lacks the same explicit focus guard; widget-level event consumption may affect observed delivery, but ownership cannot be proven from this handler alone.
- Escape precedence varies: Diff, Binary Diff, Text, Image, Audio Studio, PDF and MIDI implement different close/clear/cancel behavior. The active modal viewer/prompt is dispatched before workbench-global Escape, and `update` returns while it remains active. Some viewer-specific handlers inspect Escape before calling their normal UI renderer; nested egui dialogs may have their own behavior, which requires runtime validation.
- Audio Studio save dialogs suppress tool-letter shortcuts, but other nested editors/dialogs rely on `wants_keyboard_input()` alone. Whether every nested text control reports that state in all frames was not runtime-verified.
- Desired contract for the next implementation step: modal viewers own key events while active; focused text controls own printable and modified text-entry keys; viewer actions run only when no higher-priority dialog or focused editor owns the event; workbench shortcuts run only after no modal viewer/prompt claims the frame. Preserve each viewer's documented domain controls (for example, image tool letters and MIDI playback) when focus is not in an editor. Confirm or explicitly decide the Quick Palette's intentional single-character command prefixes before broadening its focus guards.
