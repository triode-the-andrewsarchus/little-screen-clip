# Repository Guidelines

## Project Structure & Module Organization

This is a Rust 2024 Cargo workspace. Shared clipboard models, configuration, IPC, colors, and media helpers live in `crates/little-clip-core`. Keep hardware and USB-display code in `little-clip-driver`, card/text rendering in `little-clip-render`, native Gaussian scene import and GPU rendering in `little-clip-scene`, and transformations and pipeline operations in `little-clip-ops`. The `little-clipd`, `clipctl`, and `clip-workbench` crates provide the daemon, CLI, and egui workbench binaries.

`little-clip-core::presentation` currently compiles shared presentation sources from `little-clip-ops/src` through `#[path]`; run their tests against core, since ops reexports those modules.

Root `scripts/` contains supporting Python tools, `config.toml` holds runtime defaults, and `launch.sh` manages local builds and services.

## Build, Test, and Development Commands

Run commands from the repository root:

```bash
cargo build                              # Build the workspace in debug mode
cargo build --release                    # Build optimized binaries
cargo test --workspace                   # Run all unit tests
cargo test -p little-clip-ops            # Test one crate
cargo fmt --check                        # Verify Rust formatting
cargo clippy --workspace --all-targets -- -D warnings
./launch.sh build                        # Release build through the helper
./launch.sh sweep                        # Clean stale target and incremental artifacts
./launch.sh start                        # Start the local daemon
./launch.sh ui                           # Open the workbench
./launch.sh test                         # Exercise the USB display directly
```

Default `./launch.sh build` runs `scripts/build_workspace.py`: after a successful full build, it uses Cargo's complete JSON artifact graph (including fresh units and build-script outputs) to remove obsolete hashed release artifacts. It preserves all current versions/feature variants, debug artifacts and bundled helpers. Failed builds, incomplete inventories and custom/partial builds skip automatic pruning. Explicit `./launch.sh sweep` performs aggressive cleanup toward a 20 GB cache budget (`LITTLE_CLIP_TARGET_MAXSIZE` overrides it), retaining two incremental sessions per crate/configuration; this may evict active dependencies. Without `cargo-sweep`, explicit cleanup clears debug artifacts with `cargo clean --profile dev`. Serialize launch builds and sweeps with all other Cargo commands so cleanup cannot prune a compiler's active artifacts or incremental session.

`./launch.sh test` can stop a running daemon and access attached hardware; use it only when that is intended.

## Coding Style & Naming Conventions

Use standard `rustfmt` output (four-space indentation). Name modules, functions, and variables in `snake_case`; use `PascalCase` for types and traits and `SCREAMING_SNAKE_CASE` for constants. Keep modules focused on one domain. For fallible operations, return explicit `Result` values and use the project’s error types rather than panicking in normal runtime paths.

## Testing Guidelines

Keep unit tests beside the code in `#[cfg(test)]` modules. Use descriptive `snake_case` test names that state the expected behavior, such as `fixed_palette_text_is_readable`. Add targeted tests for new transformations, parsing or configuration behavior, rendering, and testable UI logic. Run the affected crate’s tests during development and `cargo test --workspace` before submitting broader changes.

## Commit & Pull Request Guidelines

Follow the existing Conventional Commit pattern with a concise scope: `feat(image): add film simulation controls`, `refactor(ui): extract shared toolbar`, or `feat(ui): improve contrast`. Use imperative summaries. Pull requests should explain the behavior change, list validation commands and results, link relevant issues when available, and include screenshots or GIFs for workbench changes.

## Runtime Configuration & Hardware

Do not commit personal display, compositor, or desktop settings. Keep `config.toml` changes reloadable, and preserve virtual-mode behavior when no supported USB display is attached.

The workbench must remain a non-resizable, centered, single-instance popup for Niri's fixed-size floating behavior. Screen-adaptive sizing must be resolved before the window opens, with fixed-size hints in place at mapping; do not enable window resizing/maximizing or resize a visible window to fit. Internal panels may resize independently. Repeated `launch.sh ui` calls should focus the existing popup without requiring a Niri keybinding change.

The file manager is a separate application (`clip-file-manager`, launched with `launch.sh files`), tightly coupled to the workbench through shared library code and core services. Do not embed it as a workbench tab. Share UI chrome, fonts, viewers, and operation mechanisms as they become needed; keep application lifecycle and navigation independent. The workbench's fixed popup constraints do not apply to the file manager's ordinary resizable window. File mutations must preserve their completion results: read-style cancellation or post-operation timeouts can hide effects that already happened. Retry queue admission only. Transfer and naming requests share asynchronous read-only safety admission before mutation-worker submission and repeat checks at execution. Recursive rename and trash restore check payload trees; restore also checks metadata and the existing destination ancestor. Batch cancellation is cooperative and must still report completed items. Use atomic no-overwrite creation/rename; replacements must preserve the old destination until installation succeeds. Naming, editor saves, copy/move, restore and audio/MIDI exports retain validated output-directory handles through staging, conflict waits and installation; copy/move recheck source identity/safety after conflict choices and check old destination trees before replacement. Missing output directories use core create_content_directory to start at the closest existing ordinary target and validate each held parent before creating the next component; protected ancestor names must not reject ordinary data mounts such as /dev/shm. Audio exports pass pinned inputs through CommandRequest and an owned seekable staging descriptor to FFmpeg; clone the owned file handle instead of reopening a staging pathname. Accepted audio saves use an unbounded job lifetime so completion is not discarded after writes. Native Wayland file drags borrow eframe's display with their own event queue. Finish received moves only after complete success; outgoing source removal verifies identities and quarantines originals. Inspector relationship drags are Copy-only file references: do not scan their payload trees or activate their links on release. Native Copy-only sends skip the move snapshot; a peer cannot upgrade them into source removal. Enable egui-winit's clipboard shortcut key forwarding only for focused file lists or audio/MIDI preview strips; register the audio and MIDI strip focus targets every frame so range shortcuts retain focus. Text fields retain normal text clipboard handling.

System-interface inspection shares core's `kernel_interface` routing policy. Ordinary content readers use its pinned-handle open path; external content tools receive inherited pinned descriptors, and helper wrappers must forward those descriptors to descendants. Persistent decoder/player commands use CommandRequest::build_command with their existing owned cancellation, timeout and child lifecycle; path-based model parsers receive descriptor-backed views with guarded external resources, and model cache revisions include device/inode identity; device nodes and sysfs/procfs/cgroupfs/tracefs/debugfs/efivarfs/securityfs, LSM policy filesystems, configfs, bpffs, pstore, resctrl, binderfs, fusectl and nsfs must not enter generic content decoders or mutation paths. Passive attribute reads run only through bounded semantic helper processes, independently from media preview workers. Device-namespace directories use their bounded directory inventories; their names must not select sysfs attribute schemas. An unrecognized discovered subsystem must not inherit a schema from familiar ancestor names or select runtime-power getters. System snapshots keep separate pinned mount/type context for access interfaces and shared kernel objects; unknown context disables cache/lifetime reuse, and relationship targets revalidate their captured context. Inspector-to-browser handoffs retain the relationship, parent-directory identity and namespace through asynchronous directory reads, including same-folder reveals; failed handoffs must not retry as unguarded path navigation. Namespace-handle descriptor labels such as mnt:[inode] are not paths; retain the lookup path, keep inspection metadata-only, and exclude recreated nsfs wrapper timestamps from both snapshot and relationship identity. Ordinary FUSE data mounts remain ordinary content; fusectl connection previews read only documented counters/configuration, never abort. Outstanding requests alone do not prove a hung daemon. Trace streams/snapshots, debug payloads and security policies/keys/logs stay metadata-only; limited security facts are not a complete posture assessment. An expired request cannot release a child admission slot until the child has exited; only retired children may be reaped outside their owning request. Share kernel-object observations across `/dev` and `/sys` while keeping interface metadata separate. Udev subscription loss/resumption invalidates all prior observations and pending results; publish that epoch before changing availability. An immediately successful initial subscription keeps the startup epoch, but first success after failed attempts invalidates offline observations. Preserve libudev receive errno through Option-only iterators: WouldBlock is empty, interruption retries, and overflow/fatal errors retire coverage. Reconnect only on the dedicated event thread with bounded delay. Automatic refresh may reuse explicitly family-classified stable facts through bounded helper seeds only after object/namespace/event validation; unknown fields remain live and forced refresh bypasses seeds. Reused/retained facts keep their original observation times and generations. Fresh helper facts carry a pending provenance marker until accepted; older records without provenance remain unknown. Row retries follow system classification even when the first collection fails, and successful outcomes reset backoff immediately. Relevant events mark snapshots stale immediately while row collection still respects its five-second measurement limit. Inspector automatic updates use one-second freshness, rows use five seconds, and manual Refresh cannot coalesce with an automatic completion that reused stable values. Retained failed-read values keep their original timestamps and failure status, and cannot cross object lifetime generations. Directory double-click still navigates, with inspection exposed separately. Ordinary backing-file/mount relationships browse or reveal; kernel relationships inspect. Storage maps represent observed extents, not filesystem usage. Topology inventory diagnostics preserve typed failures and any known scan/node truncation; missing descriptors are not evidence of an exhausted budget. Explicit ordinary-file loop inspection reuses the semantic helper without reading file payloads. Preserve loop backing-path bytes, and revalidate backing-file identity and disk sequence through the child helper before following loop associations in either direction; failed or retained snapshots cannot authorize navigation. I²C/SPI maps represent kernel registrations, not physical-device scans or proof of absence. Passive collectors must not use raw bus interfaces to probe addresses, transfer bus data, or read EEPROM/register payloads. Subsystem inventory membership requires a direct subsystem association; inherited attribute context alone does not establish that a child is a device. Attribute tables use the requested group relative to its registered owner; arbitrary inherited children do not receive root schemas, and runtime-power getters require the immediate power group. Dynamic hwmon/thermal channel rules require direct registration. Global CPU/frequency, module and driver exceptions verify known root identities and documented positions; familiar path-component names alone never authorize attribute schemas. Generic sysfs child summaries scan only immediate entries, exclude directory aliases and attribute groups, and verify that child and subsystem registrations share the observed hierarchy mount; counts are bounded non-atomic registrations, not physical-device totals. Read-only firmware attributes may invoke methods; passive ACPI HID/CID previews use cached enumeration/modalias data, excluding cid/status/description/hrv. PWM metadata describes requested configuration, not measured output; capture is an active measurement and stays outside passive reads. Sleep previews describe supported/configured modes only; wakeup_count can block and stays outside passive reads. Global sysfs root summaries require identity checks, and registration-name counts are not physical-device counts. Filesystem/directory schemas share the sysfs routing guard and verify known root identities. Btrfs logical and device allocation are distinct snapshots, not capacity/free-space estimates; feature directory entries mean kernel support or mounted enablement according to scope, without reading feature getters. Powercap energy is a wrapping/resettable counter snapshot; regulator voltage/current settings do not prove actual output. RFkill software/hardware blocks remain separate; unblocked does not prove transmitter activity. Devfreq reported clocks may be cached, and exposed frequency bounds are not universal hardware limits. RPMsg bus channels, endpoint definitions and control objects have distinct schemas; signed decimal address getters preserve 32-bit address bits, and configuration does not prove a live assigned endpoint address. PTP FIFO reads consume events and stay outside passive previews; PPS assert/clear expose stored snapshots, and supported mode bits or capability counts do not prove active capture/synchronization. IIO raw/input/processed getters can initiate measurements and stay outside passive previews; legacy scan_elements and numbered buffer layouts require a directly registered owning device, and metadata reads must never enable capture or fire triggers. RTC calendar timezone is not inferred from system timezone. Watchdog devices must stay unopened for I/O; a kernel inactive flag does not prove hardware stopped. Snapshot namespace identity includes cgroup namespace; missing namespace identity disables reuse. Cgroup parent/child links require verified mount identity and revalidate origin and target on navigation. Cgroup previews select v1/v2 schemas from filesystem magic; v1 bandwidth times use nanoseconds, cpuacct.stat uses USER_HZ ticks, and memory+swap accounting is combined. Legacy large memory-limit values may be no-limit sentinels, so do not infer unlimited capacity from a guessed numeric threshold. Cgroup previews distinguish local configuration from ancestor constraints and accumulated CPU time from utilization; bounded same-mount ancestor settings are not computed as effective capacity/headroom, and nsdelegate or ownership/mode bits do not prove delegation rights; membership IDs are non-atomic observations, and passive reads must not migrate tasks or change controllers/resources. NUMA distance columns follow observed online-node order, not dense IDs; publish mapped rows only after membership validation and retain rows only across the same verified column set. Binary firmware properties require scoped decoding. Device-tree reg widths use only the immediate parent (defaults 2/1); addresses remain bus-relative and specifier cells are not Linux IRQ numbers.
