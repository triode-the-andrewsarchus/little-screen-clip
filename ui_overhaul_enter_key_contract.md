# Enter / Return Key Contract

This documents the current implementation as observed in source, not an idealized keyboard design. References use repository-relative file names and source line numbers; line numbers may move as the implementation changes. The workbench currently checks `egui::Key::Enter`; no separate `Return` key branch was found.

## Workbench routes

| Route / context | Current Enter behavior | Focus and precedence | Submission / cancellation |
|---|---|---|---|

## Current precedence observations and validation gaps

1. **Palette Enter is an explicit execute command.** It intentionally remains available while the search field is focused. Unlike ordinary typed characters, Enter executes the selected command; keep this behavior covered by a focus-state regression ([main.rs:2130-2139](crates/clip-workbench/src/main.rs#L2130), [main.rs:2225-2227](crates/clip-workbench/src/main.rs#L2225)).
2. **Audio Save Enter is an explicit form submit.** The Save control advertises Enter, and the handler submits from the dialog regardless of whether the destination, filename, or checkbox owns focus. Preserve this behavior and test that edits are included in the save request ([audio_preview.rs:2884-2906](crates/clip-workbench/src/audio_preview.rs#L2884)).
3. **Text viewer and prompt Enter use egui focus loss.** The handlers use `response.lost_focus()` plus Enter rather than a direct focused-response key event. Retain this behavior provisionally; add event regressions for focused and unfocused input so the submit/navigation behavior is proved ([main.rs:1726-1727](crates/clip-workbench/src/main.rs#L1726), [text_preview.rs:783-788](crates/clip-workbench/src/text_preview.rs#L783), [main.rs:2341-2342](crates/clip-workbench/src/main.rs#L2341)).
4. **Image shortcut labels describe focused-field submission.** Background Removal and OCR accept Ctrl/Command+Enter while a text prompt owns focus, and also accept unmodified Enter when no text editor owns focus. The current helper text is accurate for the focused-field case; retain both paths ([image_preview.rs:877-917](crates/clip-workbench/src/image_preview.rs#L877), [background_removal.rs:283-291](crates/clip-workbench/src/image_preview/tools/background_removal.rs#L283), [ocr.rs:438-444](crates/clip-workbench/src/image_preview/tools/ocr.rs#L438)).

This inventory is source inspection only; it does not prove runtime event ordering under every egui focus state.

## Precedence decisions for implementation

These decisions preserve explicit command and form-submit affordances while preventing viewer shortcuts from stealing ordinary text input:

1. An active modal prompt, viewer, or nested dialog owns Enter before the workbench behind it.
2. Quick Palette Enter remains the command's explicit execute action, including while its search field has focus. The search field is a command filter, and Enter is its documented execute affordance; typing Enter is not ordinary text content.
3. A focused editor owns Enter for text insertion unless its own control explicitly uses Enter to submit or navigate. Text Find advances the match and recipe prompts submit through their single-line fields; add event-level regressions before changing the current egui `lost_focus()` mechanism.
4. Audio Save remains a form: Enter submits as its Save button label promises, including when the destination or filename field is focused. Escape/Cancel dismisses it. Preserve this unless runtime testing shows the label is misleading or submission loses edited values.
5. Image processing Enter follows the active tool contract: unmodified Enter applies a ready operation when no text edit/modal owns focus; Background Removal and OCR additionally accept Ctrl/Command+Enter while a text prompt owns focus. Save As modal always owns Enter and has explicit Save/Cancel buttons rather than an implicit submit.
6. Viewers without an explicit Enter action do not inherit the workbench Palette action. Preserve native widget behavior for focused controls and buttons.

Implementation tests should cover the existing submit/navigation paths and modal ownership. This contract does not authorize changing command semantics solely to make every route use one global Enter rule.
