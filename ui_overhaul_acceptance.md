## Large single-line text previews, 2026-09-28

H2.2c1 splits raw text lines into UTF-8-safe display fragments of at most 4 KiB before measurement or rendering. The source remains intact for regex/literal search and full-content copy; search navigation maps the exact match byte to the fragment containing it. Regression tests verify exact fragment reconstruction, Unicode boundaries, far-end search/navigation, and the maximum text size passed to rendered galleys. `cargo test -p clip-workbench --bin clip-workbench -- --test-threads=1` passes (416 passed, 1 ignored), and formatting plus `git diff --check` pass. Live pointer selection across forced continuation fragments and performance measurements remain unverified; these are tracked separately under H2.2e7 and H2.2c6. The architecture baseline service timed out after five minutes, so no metric comparison is claimed.

H2.2c2a (`2c4fd49`) borrows Text/Markdown payloads instead of cloning them during inspector rendering and caches the Markdown/path and CSV candidate hints by selected slot and item IDs. Large raw-text Markdown hints cap UI-thread classification at 64 KiB; full classification remains part of preview preparation. H2.2c2b (`43dbb23`) moves clipboard `TextPreviewState` preparation, including full Markdown detection and source indexing, to the existing cancellable background loader; spreadsheet parse failures use the same worker for their text fallback. Tests verify a large clipboard payload remains byte-for-byte searchable and that large Markdown still opens in rendered mode. The full workbench suite passes (422 passed, 1 ignored), as do formatting and diff checks. Initial-time CSV classification over very large payloads and exact smart-preview bounds remain open under H2.2c2c; performance targets remain under H2.2c6. Architecture fitness calls timed out, so no metric comparison is claimed.

H2.2c4a (`0e8fd71`) prepares syntax-colored minimap samples in batches of at most 128 source lines per frame, requests repaint until preparation finishes, and caps retained samples at 4096 with original source-line positions for navigation. The focused minimap tests and full workbench suite pass (422 passed, 1 ignored), as do formatting and diff checks. The line budget does not bound the cost of an individual very long source line; this remains open under H2.2c4b. Architecture fitness calls timed out, so no metric comparison is claimed.

H2.2c2c (`d9c3a5a`) routes clipboard text through exact CSV validation on the existing background worker, opening valid tables as spreadsheets and sending invalid tables through the full text-preview fallback. Large text skips frame-time CSV, path, media and image-diff probes while keeping a provisional Spreadsheet action available; regressions cover valid CSV with 100 KiB of leading whitespace and malformed CSV fallback with full source preservation. Unit, network and timestamp hint badges are limited to inputs up to 64 KiB; unusually large padded values can omit those hints while ordinary Preview remains available. The workbench suite passes (424 passed, 1 ignored), along with formatting and diff checks. Architecture baseline and comparison calls timed out, so no metric comparison is claimed.

H2.2c3 is covered by the H2.2c1 fragment bound: each syntect call receives at most one 4 KiB UTF-8-safe fragment, and the renderer highlights virtualized visible rows only. This bounds work per call and limits it to the viewport, but does not establish a strict elapsed-time budget for pathological fragments or unusually tall viewports. Any stricter per-frame budget belongs with H2.2c5's cache/staged-work design; the open 4 KiB single-line case remains under H2.2c4b.

H2.2c4b (`7810e1f`) moves complete-line minimap syntax parsing to the bounded `BackgroundJobs` executor, preserving syntect state and keeping source-positioned samples capped at 4096. The source is Arc-shared from preview creation, avoiding a full UI-thread document clone at dispatch. Results publish only into the owning preview state; queue saturation retries after repaint. Dropping the preview cancels queued work and suppresses stale publication, but a syntect call already in progress cannot be interrupted. The queue retry regression and full workbench suite pass (426 passed, 1 ignored); formatting and diff checks pass. A pathological logical line can still consume unbounded worker time.

H2.2c5 retention audit: the preview does not retain per-row egui galleys. Search ranges now use an exact disk-backed spool, while line starts, code fragments, source-line mapping, row heights, and Fenwick prefix entries still grow with document rows. An active minimap worker retains its shared source text until syntect returns after viewer close. H2.2c5b4b–c5d track remaining cleanup and row-index/source-retention bounds.

H2.2c5b1 (`ae7946e`) adds an exact 16-byte little-endian `{start,end}` match-range spool. It retains at most 64 KiB of records in memory, then rolls over under the app cache directory; RAII removes the temporary backing file. H2.2c5b2 (`5ffaa52`) binary-searches the first range intersecting a half-open display fragment and streams matches with constant iterator storage. H2.2c5b3 (`fdfbdc0`, with Sol-reviewed fixes in `8668406` and `ea6f239`) builds indexes on `BackgroundJobs`, coalesces rapid query changes, retries queue saturation, cooperatively cancels stale scans, and publishes only current complete results. Search continues while Find is hidden. Spool read failures invalidate result state and display an error; out-of-range lookups do not invalidate valid results. The 43 focused text-preview tests pass, and the independent serial workbench suite passes (443 passed, 1 ignored); formatting and diff checks pass. Direct cleanup tests for replacement/cancellation/viewer close remain open under c5b4b.

H2.2e1 adds `unwrapped_raw_line_scrolls_horizontally_without_eliding_its_end`, which sends an egui horizontal wheel event to a long unwrapped code row, waits for scroll animation, and confirms the far edge becomes visible while the complete galley remains unelided. ## Remaining image worker cancellation audit, 2026-09-27

The Sol source audit found several workers that prevent stale publication without stopping the underlying work. Background-removal, depth-map, Creative FX depth/alpha-mask, and OptiPNG child processes keep running after a stale receiver or viewer is dropped. Film Look, Creative FX, conversion, and barcode full-image workers finish their current work after invalidation. Creative FX generates all seven thumbnails even after sends fail; Film Look checks a failed send between stock thumbnails. OCR mode-exit/viewer-drop cancellation kills the process group after PID publication, while stale-input polling waits for completion and cancellation can race initial PID publication. These specific gaps are split into H2.1h4e–h4h in the task tree; this is source audit evidence, not cancellation runtime evidence.

H2.1h4f1–f2 are implemented. OCR now stores one per-run `ImageToolProcessControl`, shared with the process-group spawn helper. A stale captured input immediately cancels the group and clears loading state silently; explicit Cancel and the existing mode-exit path retain their cancellation toast. The spawn helper checks a cancellation flag immediately after publishing the PID, closing cancellation-before-publication, while OCR keeps its piped image input, separate stdout/stderr readers, progress parsing, and current success/error messages. Unix fake-child tests verify stale-input process exit and pre-publication cancellation; the pre-publication fixture records the forked PID in `pre_exec` and confirms it is gone after the helper reaps it. Fake current-success/progress and process-failure/diagnostic tests pass, as do existing stale-success/error tests. Temporary scripts are removed. These subprocess tests are Unix-only; the installed OCR models were not exercised.

H2.1h4e1–e3 use one image-tool subprocess runner. Remove BG, Depth Map, Creative FX depth masks, and Creative FX alpha masks launch in Unix process groups, check cancellation after PID publication, and clear only their owned PID. Each request has separate process-control state. Intentional cancellation is suppressed as an operation error. Source-stamp changes terminate the corresponding Creative FX depth/alpha process; changing FX or preset intent while the source remains current leaves that process running, allowing its valid result to populate the cache without overwriting new mask intent. Viewer drop cancels both mask subprocesses. `creative_fx_depth_and_alpha_processes_stop_on_stale_source_and_viewer_drop` verifies stale-input and viewer-drop cancellation for both subprocesses with sleeping children and waits for all four PIDs to disappear. Existing `mask_result_after_switch_is_cached_but_does_not_change_new_fx_settings`, `depth_result_after_reset_is_cached_without_reenabling_mask`, `depth_result_after_preset_change_preserves_new_mask_intent`, and `alpha_result_after_reset_is_cached_without_reenabling_mask` cover cache and intent preservation; the 14-test Creative FX ownership suite passes. Prior Remove BG/Depth Map coverage includes mode exit, process-start cancellation, and current process success/failure. Temporary subprocess fixtures are removed. Tests are Unix-only; Windows process-tree termination and live AI-model cancellation were not exercised. The architecture comparison service stalled; no architecture metric is claimed for this slice.

H2.1h4e4 routes OptiPNG's temp-file CLI through the shared process control, preserving the tempfile lifetime until the child exits and retaining the existing command, exit-status, output-read, and toast behavior. Conversion generation/settings changes cancel from `schedule_conversion`; committed image changes cancel from `mark_pixels_changed`; `poll_optipng` checks the full captured request identity as a final guard; viewer drop cancels the worker. Intentional cancellation drops the worker result without reporting a process error. Unix regression `optipng_process_stops_on_settings_input_change_and_viewer_drop` uses sleeping fake child commands and checks process exit after settings change, image revision change, and viewer drop. `optipng_worker_publishes_current_success_and_preserves_bytes_on_failure` and `optipng_worker_discards_stale_success_after_input_revision_changes` still pass. These process tests are Unix-only; real OptiPNG installation and Windows process-tree cancellation were not exercised.

H2.1h4g3 now cancels the per-run conversion worker on changed settings, stale source input, and viewer teardown, and prevents an intentional cancellation from appearing as a conversion error. JPEG alpha flattening checks each row, and the JPEG encoder's checked writer observes cancellation every 4 KiB while preserving encoded bytes exactly. PNG 0.18.1 compresses its full image into an internal buffer before the outer writer receives IDAT; WebP 0.3.1 runs a synchronous libwebp encode; and `image::load_from_memory` decodes synchronously. Their calls are only checked at stage boundaries, so g3 remains open for in-call cancellation of PNG, WebP, and decode. Focused conversion tests verify request cancellation, byte parity, checked-sink boundaries, and canceled worker disconnection. The serial workbench suite passes (414 passed, one ignored); ops tests, formatting, and diff checks pass.

H2.1h4g1–g2 now use per-render cancellation flags that are set synchronously on source/parameter changes, relevant mask changes, mode exit, and viewer drop. The pinned `filmr` and `ntsc-rs` CPU packages are kept under `vendor/` with optional cancellation APIs; their original APIs remain available. Filmr checks during linearization, active pixel passes, blur rows/columns, and between pipeline stages. Creative FX checks within each of its seven effects, its mask blend, and the pinned NTSC effect's row and stage work. Workers discard cancelled output; the existing request stamps still reject stale completion, while current success and panic errors retain their prior handling. Re-entry creates a fresh render. Deterministic tests verify in-pipeline cancellation checkpoints in filmr's accurate develop and NTSC's effect path, Creative FX effect and mask-row cancellation, all seven effects against pre-change pixel fingerprints, and Filmr's successful output against the original pinned git crate with grain disabled.
